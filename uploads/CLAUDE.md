# Правила проекта

## Разметка литеров на генпланах (рамки подъездов)
- Рамка подъезда — прямоугольник с ПРЯМЫМИ углами в пиксельном пространстве (учитывать аспект изображения: перпендикуляр считать в px, не в %).
- Верхнее ребро — вдоль внешней кромки крыши (кроны деревьев могут её перекрывать — продлевать линию по чистому участку).
- Куб = светлая крыша + тёмное тело; высота рамки покрывает оба. Крыша основных литеров — всегда четырёхугольник.
- Межподъездный шов виден только на крыше — вниз через тело его продолжать мысленно.
- Соседние подъезды одного литера ДЕЛЯТ общее ребро по шву: правый край рамки одного = левый край рамки другого (одинаковые координаты, одна ось наклона на весь литер).
- Зелёные круги-геометки и соседние строения (1А, 1Б, 1В…) игнорировать — они наползают на литеры.
- Цвет рамок: #a3312b, stroke-width 2 (как в ЖК «Рекорд»).
- Пиксельные сканы кромок ненадёжны (штриховка парковок, текст, деревья): проверять примеркой — оверлей рамки на кропе, глазами.

## Карточки помещений на генпланах
Три шаблона, одинаковые во всех ЖК:
1. **Проданные** — тёмная карточка (фон #1b1916, текст #f2ede4, приглушённый #a9a196), перечёркнута крест-накрест (#e0938d), компактные отступы. Набор данных: номер и площадь, чип «Продано», номера БТИ, наименование актуальной т.т., категория актуальной т.т., данные сделки (дата продажи, факт. стоимость, выплата агенту, покупатель, годовой прирост). Кадастрового номера, рынка, аренды, управления, CAPEX/OPEX и эффективности в проданной карточке НЕТ.
2. **НТО, остановки, ЗУ** — свой сокращённый набор: место, площадь, статус, арендатор и ставка; поэтажного плана и БТИ нет.
3. **Обычные** (все остальные) — полная карточка: БТИ и кадастровый номер, рыночная цена, владелец, договор аренды (т.т., ставка, периоды, активация, каникулы, индексация, товарооборот), бывшие арендаторы, управление и платежи, CAPEX, OPEX, эффективность.

Эталон разметки — ЖК «Самолёт 3»; правки шаблона распространять на все шесть генпланов.

Порядок вывода карточек в панели подъезда зафиксирован: **в аренде → в простое → не введено в эксплуатацию → продано** (единая функция `unitRank`, внутри статуса — исходный порядок из выгрузки КП).

## Архитектура генпланов (после рефакторинга 09.09.2026)
- Вся общая логика — в `genplan_core.js` (`window.GenplanCore(DCLogic)` → базовый класс). Расчёты, сводка, карточки правятся ТАМ один раз.
- В файле очереди `class Component extends window.GenplanCore(DCLogic)` — только данные очереди (полигоны, названия, поэтажные планы, численность) и осознанные отличия (свои `renderVals`, `unitFields`, `componentDidMount`; у С3 — `cxTotalOf`, у С345 — `summaryExtra`).
- `jk_logic.js` для матрицы ГЕНЕРИРУЕТСЯ из классов очередей (обёртка `window.OMJKLogic[N] = (DCLogic) => class extends GenplanCore(DCLogic) {…}`); после правки генпланов пересобирать.
- Регрессия: `build/Стенд рефакторинга.dc.html` сравнивает сводки/карточки/renderVals всех очередей с эталоном в localStorage — прогонять после правок ядра.
- Общие реестры с ключом ЖК: `prices_net.js` (цены нетто), `rent_price.js` (прайс аренды бульвара), `sales.js` (сделки), `unit_status.js`, `utilities.js`, `volumes.js`.

## Данные
- Коммунальные услуги (utilities.js, по УПД РСО): в подстроках — фактические начисления; в итоге «Коммунальные услуги» — только периоды без действующего договора аренды (при арендаторе затраты возмещаемые и в итог не идут; расчёт по дням через `rentSegs`).
- «Аренда» в выгрузке КП по всем ЖК = помещение доступно для аренды, но простаивает.
- Личные фонды (ЛИЧНЫЙ ФОНД…, Морозов Д. С., ПРОФИТ КАПИТАЛ) — владельцы в составе ДВК, не арендаторы; «в составе ДВК» в подписи не писать.
- Названия: ЖК «Самолёт 1» (не «I очередь»).
